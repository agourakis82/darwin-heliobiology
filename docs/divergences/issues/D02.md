## Resumo
O literal `1.0e-300` vira um f64 diferente em `lean_single`: significando `6032057205060454` em vez de `6032057205060441` (expoente -997 em ambos). Madaros acerta (valor IEEE correto: `6032057205060441 × 2^-997`).

## Programa mínimo
```
fn main() -> i32 with IO, Mut, Div, Panic, Alloc {
    var a = 1.0e-300
    var e: i64 = 0
    while a < 1.0 { a = a * 2.0; e = e - 1 }
    print_int((a * 4503599627370496.0) as i64)
    print(" ")
    print_int(e)
    print("\n")
    return 0
}
```

## Comandos
```bash
bin/souc run D02.sio                                   # 6032057205060441 -997
SOUNIO_SOUC_ENGINE=lean_single bin/souc run D02.sio    # 6032057205060454 -997
```
O loop só normaliza `a` para [1,2) por multiplicações por 2 (exatas) e imprime o significando inteiro `a * 2^52`; não há aritmética inexata no programa. Mesma divergência em `sio/test_num.sio` do darwin-heliobiology (`print_tok(1.0e-300)`).

**Ambiente (medido em 2026-10-06):** Linux x86_64, `origin/main` `4871d3fa0`, `bin/souc` = `Madaros v0.80.0` (o ELF prebuilt commitado, "not built from the tree"), `SOUNIO_STDLIB_PATH=$PWD/stdlib`, `lean_single` via `SOUNIO_SOUC_ENGINE=lean_single`.
