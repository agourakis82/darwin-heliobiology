## Resumo
Dois comportamentos de `u64` com o bit 63 ligado, medidos em `origin/main` com o Madaros prebuilt:

1. `a >> k` onde `a` é **parâmetro** de função propaga o bit de sinal (Madaros). Em variável local o deslocamento é lógico. `lean_single` é aritmético em todos os casos.
2. `a > 1` com `a = 0xE220A8397B1DCDAF` é falso (comparação com sinal), nos dois motores.

Consequência prática: SplitMix64 / xorshift em `u64` saem errados assim que o estado passa por uma função; a reescrita do núcleo do darwin-heliobiology usa `i64` com deslocamento lógico explícito (`(x >> k) & mask`) e foi comprovada contra os vetores públicos do SplitMix64.

## Programas mínimos
```
fn shr(a: u64, k: i64) -> u64 { a >> k }
fn main() -> i32 with IO, Mut, Div, Panic, Alloc {
    let a: u64 = 0xE220A8397B1DCDAF
    print_int((a >> 40) as i64); print("\n")
    print_int(shr(a, 40) as i64); print("\n")
    return 0
}
```
```
fn main() -> i32 with IO, Mut, Div, Panic, Alloc {
    let a: u64 = 0xE220A8397B1DCDAF
    if a > 1 { print("unsigned-ok\n") } else { print("signed-neg\n") }
    return 0
}
```

## Comandos e saídas
```bash
bin/souc run D06.sio    # Madaros: 14819496 e -1957720   (esperado 14819496 nas duas)
SOUNIO_SOUC_ENGINE=lean_single bin/souc run D06.sio   # -1957720 / -1957720
bin/souc run D07.sio    # signed-neg   (esperado: unsigned-ok)   -- idem lean_single
```
